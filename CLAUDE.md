# CLAUDE.md — Elliott Promotional Products

Context for AI assistants working in this repo.

## What this is

A promotional-products storefront for Elliott Promotional Products (family business, London-Kitchener ON, Canada). There is **no checkout/payment** — customers browse products, add items to a cart, and submit a **quote request**; the team follows up by email. There is a password-gated admin area for managing the product catalog and suppliers.

- Brand domain: **elliottpromotional.ca** (use this everywhere; `.com` and `elliott-promotional.ca` variants in old code were mistakes)
- Brand accent: red (`red-600` for primary CTAs on the public site; admin uses `red-400`)
- Font: **Poppins** only (weights 300–700 via `@fontsource`). `--font-sans` in `app.css` is Poppins. Do not reintroduce Inter.

## Stack

- **React Router 7** (framework mode, SSR) — routes in `app/routes/`, config in `app/routes.ts`, route types from `./+types/<route>` (generated by `react-router typegen`)
- **Tailwind CSS 4** (CSS-first config in `app/app.css` via `@theme`; no tailwind.config file)
- **Drizzle ORM + Neon Postgres** — schema in `db/schema.ts`, client in `db/index.ts`
- **AWS SES** (quote/contact emails) and **S3** (product images) via `app/utils/*.server.ts`
- framer-motion (animations), Lenis (smooth scroll, wrapped in `root.tsx`), sonner (toasts), Radix dialog/sheet

## Commands

```bash
npm run dev          # dev server on :5173
npm run typecheck    # react-router typegen && tsc — keep this clean
npm run build        # production build
npm run db:push      # push schema to Neon

```

No test suite exists. Verification = typecheck + driving the app (Playwright headless works well; see git history of QA pass 2026-07).

## Environment variables (.env)

`DATABASE_URL`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_BUCKET_NAME`, `ADMIN_PASSWORD`, `SES_FROM_EMAIL`, `QUOTE_RECIPIENT_EMAILS`, and optionally `ADMIN_EMAILS` (comma-separated), `SESSION_SECRET`.

**`ADMIN_PASSWORD` and `SESSION_SECRET` are required in production** — `app/utils/auth.server.ts` throws at boot if missing (dev falls back with a console warning). Local `.env` may lack `SESSION_SECRET`; that's fine in dev only.

## Architecture notes

- **Cart** lives in `localStorage` (`app/utils/cart.ts`), key `elliott_cart`, 30-day item expiry, migrated from an old cookie automatically. Components listen for the `cartUpdated` CustomEvent (and cross-tab `storage`) to refresh the header badge. Never store the cart in a cookie again (4KB limit was silently truncating).
- **Quote submission** (`app/routes/request-quote.tsx` action): validate → **DB insert first** (source of truth) → internal SES email → best-effort customer confirmation (its failure must not fail the request). Keep this ordering.
- **Anti-spam** on public forms: isbot UA check, origin/referer check (`isLikelyBadOrigin`), in-memory rate limit (`app/utils/rateLimit.server.ts` — per-instance only), two honeypot fields (`website`, `middleName`), and a `formStart` timing gate (2.5s quote / 1.5s contact). `formStart` must be set client-side in a `useEffect` (SSR value causes hydration mismatch). Error copy for these gates must stay human-friendly — never surface "Blocked".
- **Emails** (`app/utils/ses.server.ts`): every interpolated user/cart value must go through `escapeHtml()`; image URLs through `safeImageUrl()`. Cart items come from the client, so treat all fields as untrusted.
- **Products page** (`app/routes/products.tsx`): loader does ONE `db.select().from(products)` scan and derives filters/facets/pagination in memory (catalog is ~100–200 rows; don't add more table scans). Filters, sort, and page all live in URL search params. Subcategory matching is exact case-insensitive (not substring). Page size 24.
- **Product images**: colour-specific images live in S3 under `products/{productCode}/{color}/` and are listed at runtime (`listProductImages`); `imgSrc`/`secondaryImages`/`colorImages` DB fields are the older system and are kept for backward compatibility. Fallback image is `/images/placeholder-product.svg` (an SVG in `public/images/` — the old `.png` path never existed).
- **Admin auth** (`app/utils/auth.server.ts`): shared gateway password + whitelisted email dropdown, cookie session. `requireAdminAuth(request)` guards every admin loader AND action — including `app/routes/upload-image.ts` (both its action and its presigned-URL loader; do not remove those checks). Logout is POST-only by design.
- **Gender display**: hidden for categories in `NO_GENDER_CATEGORIES` (`app/utils/categories.ts`) — use that constant, don't re-hardcode the list.
- **Colour swatches**: `getColorHex()` in `app/utils/colors.ts` handles compound names ("Heather Grey", "Caramel/Black") by matching known tokens last-word-first. Add new colour names to its map rather than special-casing in components.

## Conventions

- Internal navigation uses React Router `<Link>` / `<Form>` / `useSubmit()` — never raw `<a href>` or hand-built DOM forms for internal targets.
- Submit buttons on any mutating form get a pending state via `useNavigation()` (`disabled` + label swap) to prevent double submits.
- Home-page sections animate in via `useInView` + `animatedSections` props; section anchor ids are `about-section` and `contact-section` (Header links/scroll handlers use these).
- Barrel exports: `app/components/{sections,ui,layout,forms,admin}/index.ts` — update them when adding/removing components.
- A11y baseline maintained across the app: `aria-pressed` on toggle-style selectors, `aria-expanded`/`aria-controls` on the FAQ accordion, `aria-label` on icon-only buttons, `role="alert"` on error banners, `focus-visible:` rings, `prefers-reduced-motion` respected (global CSS rule in `app.css` + JS guards on intervals).
- Descriptions: only bullet a product description if it's newline-delimited or clearly a short comma list — see the heuristic in `products.$productId.tsx`.

## Known gaps / deferred work

- **S3 orphans**: deleting a product or removing images never deletes S3 objects (`deleteFromS3` exists but is intentionally unused — destructive, needs a deliberate decision).
- Rate limiting is in-memory per instance — bypassed if the app scales horizontally (move to Redis/Upstash then).
- Upload progress bars are simulated (`setInterval`), not real XHR progress.
- No CSRF tokens (origin/referer checking only); admin cookie is `sameSite: "lax"`.
- Footer previously linked to `/terms-of-use`, `/cookie-policy`, `/privacy-policy` — those routes never existed, links were removed 2026-07. If policy pages get written, re-add links in `app/components/forms/CompanyDetails.tsx`.
- Admin product list is client-side filtered, no pagination — fine at current catalog size.
